# Промт для отдельной сессии: бот-напоминалка «отправить позже» для ЛС ВК (WOK-769)

Скопируй блок ниже целиком в новую сессию Claude Code в репозитории postiz-app.

---

Задача WOK-769 в Linear (команда Work, проект Vezdepost): спроектировать и, если
условия выполнены, сделать бота-напоминалку «отправить позже» для личных
сообщений ВКонтакте. Отвечай на русском.

## Контекст

- Vezdepost (vezdepost.ru, app.vezdepost.ru) — бесплатный планировщик постов
  для Telegram, MAX и ВК, форк Postiz. Прочитай `docs/PROJECT.md` и `CLAUDE.md`.
- В GSC около 85% видимых запросов статьи про отложенные посты VK — про личные
  сообщения («можно ли в вк отправить отложенное сообщение», «по таймеру»).
- Исследование 15.11.2026: встроенной отложенной отправки ЛС в ВК нет.
  Отправлять от имени пользователя через API нельзя: обычное стороннее
  приложение не получает право `messages`, а с 09.2026 ВК ввёл жёсткие лимиты
  API (Kate Mobile перестал работать). «Отправить позже» есть в Telegram и в MAX
  (с 26.01.2026).
- Первый шаг — статья `/blog/otlozhennoe-soobshchenie-vk/` (WOK-768). Бот —
  второй шаг, он заблокирован WOK-768.

## Условие запуска (проверь первым)

1. Проверка спроса назначена на ~10.12.2026. Если сегодня раньше — сделай
   только дизайн (пункт «Что сделать», шаги 1–3) и остановись.
2. Если дата прошла: сравни в GSC (`sc-domain:vezdepost.ru`) статью
   `otlozhennoe-soobshchenie-vk` и запросы про ЛС до и после публикации (CTR,
   позиция, клики), в Метрике — переходы с этой статьи на app.vezdepost.ru.
   Доступы описаны в памяти и в `docs/PROJECT.md`. Если роста нет — запиши
   результат в WOK-769 и в Control Hub (`record_decision` с причиной) и не
   строй бота.

## Что сделать

1. **Правила ВК — вручную, до любого кода (обязательно для варианта д1).**
   Прочитай на dev.vk.com: правила платформы, раздел о сообщениях сообществ
   (кому сообщество может писать, `messages.allowMessagesFromGroup`, лимиты в
   сутки, есть ли окно ответа), права ключа доступа сообщества. Если сайт
   не открывается из инструмента — попроси владельца открыть страницы и
   вставить текст. Каждый вывод — с цитатой и ссылкой. Ничего не додумывай.
2. **Выбор канала.** Сравни:
   - (д1) бот в сообществе Vezdepost во ВК: человек сам пишет сообществу текст
     и время, сообщество в нужный момент присылает ему напоминание с текстом и
     ссылкой на диалог `vk.me/...`/`vk.com/im?sel=...`;
   - (в) Telegram: расширить существующего бота @vezde_post_bot или завести
     отдельного.
   Критерии: соответствие правилам ВК, где пользователь из поиска находится в
   момент запроса (он во ВКонтакте), сложность, как бот приводит людей в
   Vezdepost. Дай рекомендацию и спроси владельца, прежде чем строить.
3. **Дизайн по правилам репозитория.** Найди, как сейчас устроены бот-ассистент
   Telegram/MAX и провайдер VK, и опиши, куда встраивается напоминалка.
   Учитывай правила из `CLAUDE.md`: DTO → Controller → Service → Repository,
   отложенные задачи — через Temporal (новый workflow с версией, существующие
   workflow и параметры активити не менять), без провайдер-специфичных `if`
   в общем коде, без raw SQL, миграция Prisma, если нужна новая таблица.
4. **Реализация** — только после «да» владельца, в отдельном worktree,
   с тестами, затем ревью-агент на соответствие существующему коду.
5. В каждом напоминании — короткая ссылка на Vezdepost с UTM
   (`utm_source=reminder_bot`), без навязчивости.

## Нельзя

- Брать пользовательский токен ВК, логин или пароль, отправлять сообщения от
  имени пользователя, расширения браузера, которые жмут «Отправить» за него.
- Писать людям, которые сами не начали диалог с ботом или сообществом.
- Регистрировать сообщество, бота в BotFather, публиковать или деплоить без
  явного разрешения владельца. Новый Telegram-бот — сразу строка в
  `/Users/d.fedorenko/IdeaProjects/fedrbodr/fedrbodr-os/knowledge/bots.md`.
